# M3 — 3D table (apps/table)

> Status: **DRAFT — awaiting user approval.** Milestone: a playable, cinematic
> browser table for catan-vtt that connects to the shipped M2 room server over
> WebSocket. Visual components are delegated per user routing (hy4-preview
> primary). Mirrors mahjong-vtt/dnd-vtt apps/table pattern.

## Goal

`npm run dev` at `apps/table` (Vite :4274) renders the Catan island in 3D and
lets 3–4 friends play a full game with mouse/touch — using ONLY the M2 wire
protocol (join/op/projection/event; no kernel imports for legality; the
projection is the entire truth of the client).

## Design rulings (locked at plan time)

1. **Stack**: React 18 + Vite + three.js via @react-three/fiber + drei (same
   family as mahjong-vtt/dnd-vtt table apps). UI chrome (HUD, lobby, modals) =
   plain React/CSS overlay, not in-canvas.
2. **Renderer is a pure client of the wire.** It never imports `applyAction` or
   `legalMoves` from the kernel; `legalMoves` arrives on the projection
   (protocol.ts). Redaction is server-enforced — the table physically cannot
   show an opponent's hand. (Client rule already documented in `redact.ts`.)
3. **Geometry is procedural + data-driven from the projection**: hex board from
   `board.ports/hexes`, vertex ids for settlements/cities, edge ids for roads.
   No hand-authored board JSON — the kernel owns the map.
4. **Click → op mapping**: UI enables ONLY what the current projection's
   legalMoves allows; every interaction resolves to exactly one Op and goes
   through `op{...}`. Optimistic UI: none — wait for `event{opApplied}` (the
   room is the single source of sequencing).
5. **Assets**: CC0/MIT/primitive-materials only; no Catan GmbH art (hard rule).
   Stylized low-poly: colored hex tops + procedural terrain shading, tokens as
   primitives (houses/cities/robber as simple meshes), dice as rounded cubes.
6. **Sessions**: table talks to `ws://localhost:4273` (env `VITE_ROOM_URL`);
   lobby screen = enter roomCode + name + seat; rejoin = seatToken in
   localStorage (rotation-aware: save the newest token from every welcome).
7. **Testing**: vitest + happy-dom for non-render logic (projection→scene
   adapters, op-intent builders); visual proof = Playwright screenshots of the
   running table under `docs/e2e-review/m3-*` (browser harness can't screenshot
   WebGL headlessly — same constraint as siblings; use the established sibling
   workaround if needed).

## Phases

- **P1 scaffold** (~1 wave): `apps/table` Vite+R3F app, wire client
  (`useRoom()` hook: connect/join/receive/parse ServerMsgSchema, rejoin token),
  hex-board scene from projection, static camera. AC: board renders from a live
  seeded room; typecheck+test green.
- **P2 interaction**: HUD (turn banner, your resources, legalMoves menu),
  vertex/edge click → placement ops, dice-roll button, seven-window discard
  modal, trade + dev-card panels, robber drag-to-hex. AC: full scripted game
  playable by clicking (demo: 3 browser tabs or Playwright-driven).
- **P3 cinematic polish**: camera fly (turn handoff), build/dissolve animations,
  dice tumble, port/hex labels, sound-off by default, spectator view (seat:null
  → bird's-eye, no HUD actions), rematch + "back to lobby".
- **P4 evidence + docs**: Playwright stills for the ACs, FUNCTIONAL-SPECIFICATIONS
  §table, STATE-SNAPSHOT, plan → done.

## Acceptance criteria

- AC1: `npm run dev` :4274; join a live room server :4273 with roomCode+name.
- AC2: Full 3p game playable end-to-end through the table UI to a 10-VP winner
  (Playwright-driven or 3 manual tabs with captured evidence).
- AC3: Client imports ZERO rule logic (grep proof: no applyAction/legalMoves/
  redactForSeat in apps/table); all legality comes from shipped legalMoves.
- AC4: Rejoin after refresh restores seat + seatToken rotation honored (old tab
  fenced; matches M2 lifecycle tests).
- AC5: Spectator mode renders read-only island with broadcast events.
- AC6: No copyrighted assets: all meshes/materials procedural or CC0.

## Out of scope

Mobile layout pass, account/auth, persistence/DB, Railway deploy (user:
"more mature, then we deploy"), seeds beyond base game, voice/chat UX.

## Delegation shape

P1: 1 build agent (scaffold + wire client + board scene). Review wave:
spec + quality (READ-ONLY). P2 split by surface: (a) HUD+menus+modals,
(b) 3D interaction (clicks/drag/robber). Each gets its own 2-stage review.
